# 红利低波100 息差监控看板

## 功能

- 实时从东方财富 API 获取数据
- 股息率采用免账号的自计算 TTM（总股本加权）：中证官方100只成分名单＋东方财富分红明细和同日市值
- 息差信号仪表盘 + 历史趋势图
- 抓取失败时保留最近有效的 TTM 快照及其原口径，并显示过期状态
- 历史数据存储在浏览器 localStorage 中

## 股息率快照（每两周更新）

- 快照文件：`data/dividendSnapshot.js`
- 更新脚本：`node scripts/update-dividend-snapshot.mjs`
- 页面接口：`/api/dividend`
- 调试实时抓取：`/api/dividend?live=1`
- 成分来源：`https://oss-ch.csindex.com.cn/static/html/csindex/public/uploads/file/autofile/cons/930955cons.xls`
- 分红及市值来源：`https://datacenter-web.eastmoney.com/api/data/v1/get` 的 `RPT_SHAREBONUS_DET` 与 `RPT_VALUEANALYSIS_DET`。
- 算法：当前成分股的 `Σ(当前总股本 × 送转调整后的近12月每股税前现金分红) / Σ(当前总市值) × 100%`。
- 时间窗口以成分名单日期为截止日，左开右闭。按除息日纳入、只用“实施分配”，每10股现金先除以10；不计预案、未来派息或按报告期误归类的分红。闰日边界使用前一年月末日期。
- 分红按后续送转比例折算到当前每股口径，同日现金按送转前股本计算。当前股本发生发行、回购变化时，按当前总股本加权，并不等于将历史实际现金支付总额原样相加。
- 这是自计算值，不是中证官方 D/P1 或 D/P2，也不是基金实际分红率。配股、合并等其他公司行为未独立复核；与理杏仁的历史口径不保证完全一致。原 1%/2%/3% 息差阈值暂保留，尚未按本算法重新验证。
- 快照保存 `calculation`（窗口、覆盖率、分子、分母、算法版本）及 `components`（100只成分逐笔现金/送转事件），可独立重算核验。
- 新记录使用 `hldiv100_ttm_total_v1_records`，旧理杏仁及中证 D/P1 缓存保留原样，不混画。
- `lib/dividendSource.js` 的官方 D/P1 读取器仅用于对照；正式更新脚本和 API 调试使用 `lib/dividendTtmSource.js`，不把年度/未知期间数据冒充 TTM。

首次本地运行先执行 `npm ci --ignore-scripts`。项目锁定 SheetJS 官方发布的 0.20.3 解析旧版 XLS；Vercel 部署和 Actions 都需要安装该依赖。不需要 Token。公开接口无可用性保证，现阶段仅完成本机验证，GitHub Runner 的可用性仍需上线后确认。

### 定时更新

仓库包含 GitHub Actions 工作流：

- `.github/workflows/update-dividend-snapshot.yml`

每两周周三北京时间约 `23:10` 抓取并提交、推送快照，以 `2026-11-25` 为固定锚点，后续为 `2026-12-09`、`2026-12-23`、`2027-01-06`。GitHub cron 每周唤醒，由 `scripts/check-snapshot-schedule.mjs` 跳过间隔周，不抓取、不安装依赖、不提交。固定14天锚点可避免跨年周数奇偶导致的错位；允许任务延迟至当周周日。已取消原每日和次日补偿任务，抓取器自身的请求重试保留。手动运行工作流不受两周周期限制。

这是 GitHub 上的快照定时更新，不会自动上传电脑上尚未提交的代码。GitHub `schedule` 可能延迟，不能保证准点执行。任务不自动识别交易所节假日，数据日期以官方成分文件为准，所有市值必须与该日期一致。页面仍按真实数据年龄提示过期（抓取超过48小时或源日期超过3天），不因改为双周更新而把旧数据显示为实时数据。

TTM 抓取器对网络错误、超时、`408`、`429` 和指定 `5xx` 最多请求3次，采用退避并遵守秒数型 `Retry-After`。成分每25只批量请求并读取全部分页。校验100股覆盖、唯一同日市值、总股本×股价的单位一致性、实施状态、分红金额、除息日、重复事件与分页完整性。缺失数据不当作零或静默少算，不回退到 D/P1/D/P2；拒绝快照日期倒退。失败时保留最近有效数据及其口径、记录错误，工作流仍标失败。静态接口只读提交的快照，不要求每次打开页面访问上游。
